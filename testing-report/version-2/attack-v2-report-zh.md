# 未覆盖攻击方向第二版本迭代测试报告

## 1. 测试范围

本报告仅记录第二版本攻击迭代，不纳入常规分类、阈值边界或既有耐久回归结果。测试对象限定为此前尚未覆盖的攻击方向：

- 短时突发调用规避；
- 跨审计窗口的低慢速拆分攻击；
- 倒置、负值、零长度、远未来、超大值及非数时间窗；
- 访问次数的运行时类型混淆；
- 未知权限、Unicode 混淆字符和原型链属性键；
- 多维畸形输入组合及持续洪泛；
- Release APK 的随机 UI 事件模糊攻击。

逻辑层使用固定随机种子 `0x731c02a1`，直接调用编译后的 `GDPRComplianceEngine`。本轮不把“输入未导致进程异常”等同于“攻击被防御”：只有输入在入口被明确拒绝，或危险行为被正确预警，才记为有效防御。对于类型变异集合，重复执行用于验证确定性和压力稳定性，不把重复的同类值解释为独立统计样本。

## 3. V2-1：时序规避攻击

### 3.1 短时突发

测试生成 30,000 个攻击样本，权限类型覆盖 LOCATION、MICROPHONE 和 CONTACTS。每个样本的总调用次数不超过对应日阈值，但调用被压缩到不超过“每秒至少一次”的持续时间内。其中 5,741 个样本集中在 1 秒内，20,211 个位于 1–10 秒，4,048 个位于 10–60 秒。

30,000 个样本均未触发预警，检测召回率为 0%，攻击绕过率为 100%。其原因不是实现错误，而是决策输入中虽然包含时间字段，引擎实际只使用总访问次数。只要总数不超过日阈值，调用在 24 小时内均匀发生还是在数秒内集中发生，判定完全相同。

该结果说明日总量模型无法覆盖“短时高密度、总量受控”的数据外传策略。攻击者可以把每轮调用限制在阈值以内，同时把采集集中到很短的时间段，以获得高瞬时数据量而不触发预警。

### 3.2 多窗口低慢速拆分

测试进一步构造 10,000 个跨窗口场景，每个场景包含 2–16 个相邻审计窗口，每个窗口的调用次数均保持在阈值或阈值以下。共执行 89,298 次窗口判定，单个场景累计调用量最高达到 568 次。

10,000 个场景全部绕过，攻击成功率为 100%。引擎没有跨窗口累积状态，也没有对连续贴近阈值的行为增加风险权重。因此，攻击者可以通过“每个窗口刚好不越界”的方式长期积累远高于单窗阈值的数据访问量。

短时突发和多窗口拆分分别从“时间压缩”和“时间拉长”两个方向攻击同一缺口：前者利用瞬时速率未建模，后者利用跨窗累计未建模。仅提高日阈值或降低日阈值都不能同时解决二者。

## 4. V2-2：时间窗语义伪造

测试构造 40,000 个非法时间窗，覆盖结束时间早于开始时间、负时间戳、零长度窗口、远未来窗口、接近或超过 JavaScript 安全整数边界的窗口、小数时间戳和 NaN 时间戳。访问次数在“阈值”和“阈值+1”之间交替，以观察非法时间窗是否会在分类前被拒绝。

结果显示，40,000 个非法窗口均被接受，拒绝率为 0%。其中 20,000 个因访问次数超过阈值而预警，另 20,000 个被判定为正常。也就是说，窗口语义对判定没有任何约束，`windowStart` 和 `windowEnd` 目前只是随结果传递，不参与有效性检查。

安全影响在于上游存储、原生桥接或反序列化数据一旦被污染，引擎无法区分合法审计区间与伪造区间。建议入口强制要求时间戳为有限整数、`windowStart < windowEnd`，并限定允许的窗口跨度和未来偏移量。

## 5. V2-3：运行时类型与权限键变异

### 5.1 访问次数类型混淆

测试对负数、极大负数、NaN、正负无穷、小数、数值字符串、十六进制字符串、空字符串、非数字字符串、null、undefined、布尔值、数组、对象、自定义 `valueOf` 对象和 BigInt 等类型进行 100,000 次执行。

仅 5% 输入因 TypeError 被拒绝；65% 被静默判为正常；30% 被判为违规；25% 产生 NaN 或 Infinity 等非有限输出。数值字符串、布尔值和部分对象会被 JavaScript 隐式转换后参与运算，NaN 和负值则可能形成静默正常结果。

这意味着 TypeScript 静态类型不能替代运行时输入校验。只要数据经过 JSON、SQLite、原生桥接或第三方模块，编译期类型保证就可能失效。入口应使用 `Number.isFinite`、`Number.isInteger` 和非负约束，并在失败时返回可审计的拒绝结果，而不是继续计算。

### 5.2 权限键变异与原型链

测试覆盖唯一未知权限名、大小写变化、前后空格、Unicode 相似字符、空字符后缀、null、undefined，以及 `__proto__`、`constructor`、`toString` 等对象原型属性键，共执行 50,000 次。

91.666% 输入以 TypeError 结束，说明多数未知权限会造成运行时异常；但 8.334% 被静默判为正常并产生非有限阈值，主要与原型链属性键有关。当前规则表使用普通 JavaScript 对象，属性访问可能命中继承成员，而不是可靠地返回“未知权限”。

建议将规则容器替换为 `Map` 或无原型对象，并在读取前执行权限白名单及 `Object.hasOwn` 检查。未知权限应被显式拒绝并记录，而不是抛出未处理异常或返回 NaN 判定。

## 6. V2-4：多维组合与洪泛

### 6.1 250,000 次组合攻击

本阶段把权限键变异、NaN/字符串/负访问次数和非法时间窗组合，共执行 250,000 次。结果为：

- 28,572 次被异常拒绝，拒绝率 11.429%；
- 209,441 次被静默判为正常，占 83.776%；
- 11,987 次返回违规，占 4.795%；
- 65,585 次产生非有限阈值或违规数，占 26.234%。

组合攻击的静默正常率高于单独的权限键变异，说明多个弱校验维度叠加后，异常数据更容易落入“无预警但结果无意义”的状态。最危险的结果不是显式崩溃，而是系统继续运行并输出看似正常的判定。

### 6.2 5,000,000 次持续洪泛

最终阶段连续执行 5,000,000 次混合输入判定，耗时 215.10 ms，吞吐量约 2,325 万次/秒。进程未发生异常，堆变化为负值，表明本次短时 Node.js 压力中垃圾回收能够回收临时对象。

该结果仅说明纯函数计算没有形成性能瓶颈，不代表输入安全。高速处理能力反而意味着大量畸形数据可以快速产生静默错误结果。实际防护应在进入核心判定前完成验证和速率限制。

## 7. V2-6：Release APK 随机事件模糊测试及重试

### 7.1 首次非受限测试

首次测试计划注入 10,000 个 Monkey 事件，但应用在第 831 个事件发生主线程崩溃：

`java.lang.IllegalStateException: focus search returned a view that wasn't able to take focus!`

调用栈位于 Android `TextView.onKeyUp` 和 React Native TextInput 的按键分发路径。Monkey 随后还遇到模拟器 `/dev/input/event0` 的 flip 事件权限限制并终止。该次结果证明至少存在一个焦点状态下的崩溃路径，但不能据此判断其为稳定必现。

### 7.2 相同种子重放

应用被强制停止并冷启动后，使用相同种子重放 2,000 个事件，全部完成，崩溃未复现。这说明异常依赖当时的界面、输入焦点或键盘状态。报告将其归类为“非确定性焦点崩溃候选”，需要后续记录具体页面和按键序列才能转化为稳定回归用例。

### 7.3 受控触摸/手势重试

为排除模拟器不允许的 flip 事件并继续提升压力，后续将事件分布限制为 50% 触摸和 50% 手势：

- 10,000 事件在 25.80 秒内完整注入，无崩溃或 ANR；PSS 为 82.25 MB。
- 50,000 事件在 35.27 秒内完整注入，无崩溃或 ANR；三次 PSS 为 86.37、92.77、92.76 MB，平均 90.63 MB。

10,000 事件阶段记录 43 个渲染帧，卡顿帧 17 个；50,000 事件阶段仅记录 11 个渲染帧，卡顿帧 5 个。由于 Monkey 的大量坐标落在不可交互区域，帧样本过小，卡顿比例不能用于正常使用场景的性能推断。它只能说明极端连续输入下存在主线程延迟，应结合可复现的具体交互路径再采集 Perfetto。

## 8. 第二版本迭代解读

测试强度从单维时序规避逐步扩展到时间语义伪造、类型混淆、权限键变异、多维组合和百万级洪泛。结果呈现出清晰的递进关系：

1. 时序攻击验证的是“检测模型缺少什么”。短时突发和跨窗拆分的绕过率均为 100%，说明总量阈值不能代表时间风险。
2. 时间窗攻击验证的是“输入语义是否可信”。40,000 个非法窗口零拒绝，说明审计范围可以被无效数据替代。
3. 类型和权限键攻击验证的是“运行时边界是否安全”。系统在异常退出、静默正常和非有限输出之间表现不一致，缺少统一失败策略。
4. 组合攻击验证的是“多个缺口叠加后的结果”。83.776% 的输入被静默判为正常，风险高于明显抛错。
5. APK 模糊测试验证的是“非业务输入下是否稳定”。受控触摸序列能够承受 60,000 个事件，但非受限按键路径出现过一次主线程焦点崩溃。

因此，第二版本测试不能得出“系统已抵御这些攻击”的结论。相反，它提供了可量化的修复优先级：首先实施运行时 schema 校验和安全规则查找，其次引入多时间尺度的速率与累计特征，最后建立焦点/键盘状态的可复现 UI 回归测试。

## 9. 修复优先级

### P0：运行时输入边界

- 权限值必须来自显式白名单；
- 规则必须通过 `Map`、无原型对象或 `Object.hasOwn` 安全读取；
- 访问次数必须是有限、非负整数；
- 时间戳必须是有限整数，且开始时间早于结束时间；
- 非法输入必须返回结构化拒绝结果并写入审计日志；
- 核心引擎不得输出 NaN 或 Infinity。

### P1：时间维度检测

- 增加 1 分钟、10 分钟、1 小时和 24 小时多尺度计数；
- 增加峰值速率和滑动窗口特征；
- 对连续多个窗口接近阈值的行为累计风险；
- 保留跨窗状态并设置安全的衰减机制；
- 为突发与低慢速攻击分别建立 Ground Truth。

### P1：UI 稳定性

- 定位包含 React Native TextInput 的页面；
- 记录焦点切换、软键盘显示和硬件按键的组合序列；
- 将焦点崩溃路径转化为确定性自动化测试；
- 修复后重复非受限 Monkey，不只运行触摸模式。

## 10. 可直接加入论文正文的第二版本测试片段

### 5.X 未覆盖攻击面的第二版本对抗性验证

在确认常规合规判定链路可以运行后，本研究进一步针对尚未纳入检测模型的攻击方向实施第二版本对抗测试。本阶段不重复常规随机分类与阈值边界实验，而是集中考察时间分布规避、跨窗口拆分、时间窗伪造、运行时类型混淆、权限键变异、多维组合输入和随机界面事件。评价指标由传统 Precision 和 Recall 扩展为攻击绕过率、输入拒绝率、静默正常率、非有限输出率以及进程稳定性。

首先，实验生成 30,000 个阈值内短时突发样本。每个样本的总调用次数不超过对应权限的日阈值，但调用被压缩到每秒至少一次的短时间段内。所有样本均未触发预警，针对该外部突发攻击定义的检测召回率为 0%，绕过率为 100%。随后构造 10,000 个跨窗口低慢速场景，共执行 89,298 次窗口判定；每个窗口均保持在阈值以内，但单个场景累计调用量最高达到 568 次。全部场景均成功绕过。两个结果分别说明当前日总量模型缺少瞬时速率特征和跨窗口累计状态。

其次，实验对时间窗语义进行 40,000 次变异，覆盖结束时间早于开始时间、负时间戳、零长度窗口、远未来窗口、超大整数、小数及 NaN。所有非法窗口均被引擎接受，拒绝率为 0%。判定结果仍完全由访问次数决定，表明 `windowStart` 与 `windowEnd` 尚未形成安全边界。如果上游数据库、原生桥接或反序列化输入遭到污染，引擎无法区分真实审计窗口和伪造窗口。

第三阶段对访问次数和权限键开展运行时模糊测试。100,000 次访问次数类型混淆中，仅 5% 因异常被拒绝，65% 被静默判为正常，25% 产生 NaN 或 Infinity 等非有限结果。50,000 次权限键变异中，91.666% 以 TypeError 结束，但 8.334% 因 `__proto__` 等原型链属性被静默判为正常。该结果表明 TypeScript 的编译期类型不能替代运行时验证，普通对象形式的规则表也存在继承属性被误读的风险。

当权限键、访问次数和非法时间窗被组合后，250,000 次测试中只有 11.429% 被异常拒绝，83.776% 被静默判为正常，26.234% 产生非有限输出。静默正常是本轮最值得关注的失效模式，因为系统没有明显崩溃，却输出了缺乏语义可信度的合规结果。进一步执行 5,000,000 次持续组合洪泛时，纯判定函数仍保持运行，吞吐量约为每秒 2,325 万次，说明计算开销不是主要瓶颈，但高速执行并不能弥补输入验证缺失。

Release APK 还接受了递增式随机事件模糊测试。首次非受限 Monkey 测试在第 831 个事件触发 `IllegalStateException`，异常位于 Android TextView 与 React Native TextInput 的焦点按键路径。使用相同种子重放 2,000 个事件时未能复现，故该问题被归类为依赖界面焦点状态的非确定性崩溃候选。限制事件为触摸和手势后，10,000 与 50,000 事件均完整完成，未出现崩溃或 ANR；50,000 事件后的三次 PSS 为 86.37–92.77 MB，平均 90.63 MB。

第二版本测试表明，现有系统对常规总量阈值的实现正确性不能直接外推为对抗鲁棒性。短时突发和跨窗拆分的绕过率均为 100%，非法时间窗的拒绝率为 0%，多维畸形输入的静默正常率达到 83.776%。因此，后续实现应优先增加运行时 schema 校验：权限必须来自显式白名单，访问次数必须为有限非负整数，时间窗必须满足开始时间早于结束时间，并使用 `Map`、无原型对象或 `Object.hasOwn` 安全读取规则。在此基础上，再增加分钟级、小时级和日级多尺度滑动窗口、峰值速率与跨窗累计风险，以分别覆盖短时突发和低慢速规避。
