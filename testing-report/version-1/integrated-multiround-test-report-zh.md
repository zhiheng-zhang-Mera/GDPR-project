# Android 权限审计框架多轮递进测试与结果解读

## 1. 测试目的与证据边界

本次测试以论文第 5 章的验证框架为依据，将既有 Release APK 专项测试固定为第一轮，并按“基线验证—独立随机验证—边界与对抗验证—APK 耐久回归”的顺序逐步增加难度。评价指标包括混淆矩阵、Precision、Recall、F1-score、内存、冷启动时间、帧性能和运行稳定性。

为避免把同一阈值公式同时用于被测系统和 Ground Truth 而造成循环论证，第二轮开始使用与应用模拟器分离的独立判定器。对零误判样本同时给出 95% Wilson 置信区间下限，并用“3/N”规则估计零观测错误时真实错误率的 95% 上界。需要强调的是，各轮样本的生成方式不同，不能把全部样本简单视为同分布独立样本；因此统计结论以分轮报告为主。

## 2. 测试环境

- 代码分支：`7-31-compress`
- 提交：`ba0a443b1da253bab9bd9b6fa5536d9c4cedcc05`
- APK：Release、x86_64、Hermes、R8、资源压缩
- APK 体积：28.68 MB；Debug APK 为 81.42 MB，压缩 64.8%
- 设备：Android Emulator `emulator-5554`
- 系统：Android 16 / API 36，320 × 640
- 应用包：`com.anonymous.mymobileapp` 1.0.0

|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 第一轮 | Release APK 单批基线 | 50 | 40 | 0 | 10 | 0 | 100% | 100% | 100% | 92.865% |
| 第二轮 | 独立判定器 Monte Carlo | 1,000 | 930 | 0 | 70 | 0 | 100% | 100% | 100% | 99.617% |

四轮累计得到 8,550 个分类观察且未出现误分类。由于第二、三轮为逻辑层测试，第一、四轮为同一 APK 中的结构化集成测试，累计值只用于描述覆盖规模，不作为单一同分布样本计算统一置信区间。

## 4. 第一轮：Release APK 基线记录与解读

第一轮在 Release APK 中执行一次 50 轮合规模拟，得到 TP=40、FP=0、TN=10、FN=0，Precision、Recall 和 F1-score 均为 100%。冷启动耗时 948 ms；启动稳定 10 秒后 PSS 为 99.68 MB、RSS 为 207.60 MB；审计后 3 次 PSS 为 87.99、87.92 和 87.93 MB，均低于论文设定的 150 MB 上限。

该轮证明了 Release 构建可独立安装和运行，能够完成从界面操作、模拟配置生成、合规判定到结果呈现的基本链路。但 N=50 时，即使未观察到错误，95% Wilson 准确率下限仍只有 92.865%，零错误率的“3/N”上界约为 6%。因此，第一轮适合作为功能性基线，不能单独支撑“算法在复杂输入下稳定可靠”的强结论。

## 5. 第二轮：独立判定器 Monte Carlo 测试与解读

第二轮使用固定随机种子 `0x7f31c0de` 生成 1,000 个独立样本，覆盖 LOCATION、MICROPHONE、CONTACTS 三类权限及 0–300 次访问计数。Ground Truth 由独立判定器计算，不调用应用内模拟器的 `expectedViolation`，从而降低同源判定偏差。

本轮结果为 TP=930、FP=0、TN=70、FN=0，Precision、Recall 和 F1-score 均为 100%。95% Wilson 准确率区间下限提高至 99.617%；在零误判条件下，真实错误率的 95% 上界约为 0.3%。这表明现有引擎对于其已定义的“总访问次数超过固定动态阈值”判定规则具有稳定且可重复的实现一致性。

与第一轮相比，第二轮的主要增量不是指标数值变化，而是证据强度提升：样本量扩大 20 倍，Ground Truth 与应用模拟器解耦，统计不确定性明显收窄。但样本分布中违规样本占比较高，因此该轮不能替代对阈值附近正常样本的专门验证。

## 6. 第三轮：边界、时序及畸形输入对抗测试与解读

### 6.1 阈值边界攻击

第三轮首先针对每类权限阈值的 `-2、-1、0、+1、+2` 五个位置进行分层采样，每个位置重复 400 次，共 6,000 个样本。结果为 TP=2,400、FP=0、TN=3,600、FN=0，Precision、Recall 和 F1-score 均为 100%，95% Wilson 准确率下限为 99.936%，零错误率上界约为 0.05%。

该结果说明阈值比较不存在常见的 off-by-one 缺陷：访问次数等于阈值时保持合规，只有严格超过阈值才触发违规，与当前代码定义一致。第二轮和第三轮合计 7,000 个独立逻辑样本无误判，其描述性准确率为 100%，95% Wilson 下限为 99.945%。

### 6.2 突发时序规避

测试构造了 3,000 组“总调用次数相同、时间分布不同”的配对样本，一组在 24 小时均匀分布，另一组集中在 1 分钟内突发完成。3,000 组判定结果全部保持不变。这不是现行计数规则内部的分类错误，而是规则覆盖缺口：当前引擎只读取 `accessCount`，不使用 `triggerTimes`、`windowStart`、`windowEnd` 或峰值速率，因此无法区分低风险的均匀访问与具有数据外传特征的短时突发。

该发现与论文关于“50 次调用集中在 1 分钟内可能逃逸日总量阈值”的局限性一致。后续可增加峰值速率、滑动时间窗或时间序列异常分数作为辅助判定，但在实现前不应声称系统已经覆盖突发攻击。

### 6.3 时间窗篡改

倒置时间窗、负时间戳、零长度时间窗和远未来时间窗均被引擎接受，且只要访问次数相同就返回相同判定。说明当前合规引擎没有验证 `windowStart ≤ windowEnd`、时间戳合理范围或审计窗口长度。若上游采集层遭到数据污染，攻击者可能通过伪造窗口影响审计语义，而引擎本身不会拒绝异常记录。

### 6.4 畸形输入与类型混淆

负访问次数被静默判定为正常；小数访问次数被接受；NaN 产生 NaN 违规数并被静默判定为正常；正无穷被判定为违规；数值字符串被 JavaScript 隐式转换后参与计算；未知权限导致运行时异常；`__proto__` 权限键产生 NaN 阈值并被静默判定为正常。

这些输入通常不应由正常 TypeScript 调用产生，但可能通过损坏的持久化数据、原生桥接、反序列化或测试接口进入运行时。建议在引擎入口进行运行时 schema 校验：权限值必须属于白名单，访问次数必须为有限、非负整数，时间窗必须合法，并使用无原型映射或显式 `hasOwn` 检查规则键。

### 6.5 高频洪泛

逻辑层连续执行 1,000,000 次判定耗时 47.32 ms，约 2,113 万次/秒，Node.js 堆增量约 0.94 MB。该结果说明纯判定函数本身不是性能瓶颈，但它不包含 Android 桥接、数据库、AppOpsManager、WorkManager 和 UI 渲染成本，因此只能证明算法计算开销很小，不能替代设备端性能测试。

## 7. 第四轮：APK 端耐久回归与解读

第四轮在同一 Release APK 中连续执行 30 批 50 轮模拟，共形成 1,500 个集成样本。按每批 40 个违规样本和 10 个正常对照计算，累计 TP=1,200、FP=0、TN=300、FN=0，Precision、Recall 和 F1-score 均为 100%；95% Wilson 准确率下限为 99.746%，零错误率上界约为 0.2%。整个序列耗时 19.17 秒，进程持续存活，未捕获崩溃、ANR 或 React Native JavaScript 异常。

在第 5、10、15、20、25、30 批采集的 PSS 分别为 115.16、99.63、92.97、102.09、99.32 和 112.50 MB，平均 103.61 MB，峰值 115.16 MB，均低于 150 MB 目标。PSS 在垃圾回收和分配波动下没有呈单调增长，未出现明显的短时累积泄漏迹象。

本轮共渲染 630 帧，其中 66 帧被标记为卡顿帧，比例为 10.48%；帧时长 P50、P90、P95、P99 分别为 21、31、34、46 ms，Missed Vsync 为 16。与第一轮只有 20 帧的样本相比，第四轮提供了更稳定的 UI 性能观察。由于测试采用每 500 ms 一次的高频自动点击，负载显著高于日常 24 小时一次的审计操作，因此 10.48% 卡顿率应解释为压力条件下的上界，而不是正常使用体验；但它仍提示可通过后台线程执行批量模拟、减少重复状态更新或合并渲染来优化压力场景。

## 8. 迭代解读

第一轮回答“功能是否可运行”，第二轮回答“扩大随机样本后规则实现是否一致”，第三轮回答“阈值边界和对抗输入下是否仍然可靠”，第四轮回答“同一 APK 连续重复运行时是否保持正确和稳定”。随着测试难度提升，分类指标保持 100%，而结论从单纯的功能通过逐步收敛为两个更精确的判断：

1. 在现有威胁模型的已实现部分，即三类敏感权限的日总量阈值判定中，算法实现具有高一致性。独立逻辑样本达到 7,000 个，95% Wilson 准确率下限为 99.945%。
2. 准确率高不等于攻击面覆盖完整。时序突发、时间窗伪造和畸形输入属于现有模型未处理或未验证的输入维度，不能被 100% Precision/Recall 掩盖。

因此，本次迭代没有把所有对抗样本混入同一混淆矩阵。边界样本属于现有判定域，可计算 Precision/Recall；突发与窗口攻击暴露的是模型能力缺失，在定义新的 Ground Truth 和检测规则前，应作为覆盖缺口单独报告。这种区分可以避免用不适用的标签夸大或贬低系统性能。

## 9. 总结解读与论文可用结论

综合四轮测试，框架在 Release 构建中完成了 8,550 个分类观察，未出现 FP 或 FN；其中最具统计解释力的独立逻辑层包含 7,000 个样本，准确率为 100%，95% Wilson 置信区间下限为 99.945%。APK 端 1,500 个结构化集成样本同样无误判、无崩溃和 ANR，PSS 峰值 115.16 MB，满足论文提出的低于 150 MB 的内存目标。

这些结果支持“当前日总量阈值判定实现正确且在模拟器压力下稳定”的结论，但不支持“已验证所有现实攻击”的表述。实体设备 24/72 小时 WorkManager 调度、Doze、厂商日志清理、真实电池消耗、真实恶意 APK 权限调用，以及跨 Android 版本兼容性仍未由本轮加速测试覆盖。论文正文应将本次结果归类为逻辑层与模拟器集成层证据，并把真实设备长期测试保留为独立验证或研究局限。

## 10. 可直接加入论文正文的测试报告片段

### 5.X 多轮递进式压力测试与统计验证

为提高实验结论的可信度，本研究在初始功能验证的基础上设计了四轮递进式测试。测试从 Release APK 的单批集成验证开始，随后引入独立 Ground Truth 的 Monte Carlo 随机测试、阈值边界对抗测试以及 APK 端连续耐久回归。评价指标包括 TP、FP、TN、FN、Precision、Recall、F1-score、95% Wilson 置信区间、内存占用和帧性能。对于零误判样本，另采用“3/N”规则估计真实错误率的 95% 上界。各轮样本生成机制不同，因此本文分别报告每轮结果，不将全部样本简单视为同分布独立样本。

第一轮在经 R8 和资源压缩的 Release APK 中执行 50 轮合规模拟，得到 TP=40、FP=0、TN=10、FN=0，Precision、Recall 和 F1-score 均为 100%。APK 冷启动耗时为 948 ms，审计完成后的三次 PSS 稳定在 87.92–87.99 MB。尽管该轮验证了端到端基本链路，但 N=50 时 95% Wilson 准确率下限仅为 92.865%，说明该结果更适合作为功能基线，而非充分的统计证据。

第二轮采用固定随机种子生成 1,000 个独立样本，覆盖 LOCATION、MICROPHONE 和 CONTACTS 三类权限及 0–300 次访问计数。与应用内模拟器不同，本轮由独立判定器生成 Ground Truth，以降低同源判定偏差。结果为 TP=930、FP=0、TN=70、FN=0，Precision、Recall 和 F1-score 均为 100%，95% Wilson 准确率下限提高至 99.617%，零观测错误对应的真实错误率 95% 上界约为 0.3%。

第三轮重点考察阈值附近的规避行为。测试在每类权限阈值的 -2、-1、0、+1 和 +2 位置分别重复采样，共形成 6,000 个分层样本。结果为 TP=2,400、FP=0、TN=3,600、FN=0，95% Wilson 准确率下限为 99.936%。该结果表明当前实现不存在阈值比较的 off-by-one 错误：访问次数等于阈值时保持合规，严格超过阈值时触发预警。第二、三轮合计 7,000 个独立逻辑样本无误判，准确率为 100%，95% Wilson 下限为 99.945%。

在扩大分类样本的同时，本研究进一步测试了上一轮未覆盖的攻击方向。3,000 组配对样本分别采用 24 小时均匀分布和 1 分钟突发分布，但保持总访问次数相同，所有配对均得到相同判定。这说明当前引擎只基于日总访问量，不具备短时峰值检测能力。倒置、负值、零长度和远未来时间窗同样未被拒绝；NaN、未知权限及特殊属性键等畸形输入还会导致静默正常判定、NaN 结果或运行时异常。上述现象不属于现有总量阈值规则内部的误分类，而是威胁模型与输入验证的覆盖缺口。未来版本应增加滑动时间窗或峰值速率特征，并在引擎入口实施权限白名单、有限非负整数和合法时间窗校验。

第四轮在 Release APK 中连续运行 30 批 50 轮模拟，共得到 1,500 个结构化集成样本。累计 TP=1,200、FP=0、TN=300、FN=0，Precision、Recall 和 F1-score 均为 100%，95% Wilson 准确率下限为 99.746%。测试历时 19.17 秒，期间未发生崩溃、ANR 或 JavaScript 异常。六个内存采样点的 PSS 为 92.97–115.16 MB，平均 103.61 MB，满足低于 150 MB 的设计目标，且没有呈现随批次单调增长的短时泄漏趋势。在高频自动点击压力下，630 帧中有 66 帧被标记为卡顿帧，卡顿率为 10.48%，P50、P90 和 P95 帧时长分别为 21、31 和 34 ms。由于该交互频率远高于系统正常的低频审计场景，该结果应视为压力上界，但仍提示批量计算与界面刷新之间存在进一步解耦优化空间。

综上，四轮测试共形成 8,550 个分类观察，未发现 FP 或 FN；其中 7,000 个独立逻辑样本提供了最强的统计证据。实验结果支持本框架在已实现的三类敏感权限日总量阈值判定范围内具有正确、稳定且低内存开销的实现。然而，结果同时表明高分类准确率不能替代攻击面覆盖分析。短时突发、时间窗伪造、异常反序列化输入、真实设备上的 Doze 与厂商日志清理仍需在后续工作中通过峰值检测、运行时 schema 校验和长期实体设备实验进一步验证。
